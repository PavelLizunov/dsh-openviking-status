# dsh-openviking-status: Доменная модель и концепция

## Контекст

Плагин статусной строки и визуализации состояния OpenViking в интерфейсе DeepSeek Harness (DSH Desktop / Web).

## Глоссарий (Ubiquitous Language)

### Session Status (Состояние сессии)

- **Active Session**: Текущая сессия чата DSH, идентифицируемая UUID (в OpenViking транслируется в `dsh-session-<uuid>`).
- **Peer ID**: Идентификатор рабочего контекста (репозитория или рабочей папки), определяющий скоуп памяти в OpenViking.
- **Pending Tokens**: Количество токенов диалога, накопленных в текущей сессии с момента последнего коммита. При достижении порога (`commitTokenThreshold`, по умолчанию 20 000) инициируется автокоммит.
- **Commit**: Двухфазная фиксация сессии. **Phase 1 (Archive)** — синхронная: сырые сообщения архивируются в VikingFS, ответ возвращает `task_id`. **Phase 2 (Extraction)** — асинхронная: фоновая задача извлекает сущности, предпочтения и события. Запускается вручную (`Commit Now`) или автокоммитом по порогу Pending Tokens.

### Memory Extraction (Извлечение памяти, Фаза 2)

- **Extraction Task**: Фоновая задача демона (`task_type: session_commit`), выполняющая Phase 2. Скоуп — одна сессия, привязка через `resource_id`. Жизненный цикл статусов: `pending` (в очереди) → `running` (воркер извлекает) → `completed` | `failed`. Промежуточного прогресса _внутри_ задачи демон не отдаёт: под-стадии и счётчик «N из M» недоступны.
- **Resource Id**: Идентификатор ресурса задачи, равный сессии в форме `dsh-session-<uuid>`. Фильтрация задач по нему — точная (exact match): формы `dsh-<uuid>` и голый `<uuid>` не совпадают, поэтому идентификатор сессии требует разрешения перед запросом.
- **Extraction Result**: Итог завершённой задачи: число записанных и отредактированных воспоминаний (`memory_write`, `memory_edit`), расход токенов, ссылка на архив. Заполняется только по завершении.
- **Execution Events**: Лента статусных событий задачи (`created → running → completed`) с таймстампами. Даёт длительность и историю переходов, но не дробь прогресса. Подгружается лениво, только при явном раскрытии лога.
- **Session Backlog (Хвост сессии)**: Незавершённые задачи текущей сессии — `pending` (в очереди) и `failed` (не доехали). Показывается только когда непуст: заполненный «хвост» из completed прогрессом не является (счётчик коммитов растёт монотонно и не финиширует), поэтому шкала completed/all как прогресс-бар отвергнута.

### Memory Recall (Подмешивание памяти)

- **Profile Block**: Долговременный профиль пользователя и сущностей (`<openviking-context source="profile">`), инжектируемый при старте диалога.
- **Recall Block**: Релевантные воспоминания (`<openviking-context>`), найденные поиском по тексту первого сообщения пользователя.
- **Recalled Count**: Число документов/чанков памяти, подгруженных в текущую сессию.

### UI Presentation (Интерфейс)

- **Stats Row (Строка статистики)**: Ряд пассивных показаний под композером (`conversation.composer.dock`), где DSH показывает чипы вроде `24 turns 645 steps`. Место Status Chip — здесь, а не внутри карточки ввода.
- **Status Chip**: Ячейка в Stats Row, отображающая `OV: <recalled> rec · <pending>k pend`. Оформление повторяет соседние чипы: без собственного фона и рамки, цвет и шрифт наследуются от строки.
- **Status Popover**: Всплывающая карточка по клику на Status Chip: статус сервера, Peer ID, шкала Pending Tokens, список подмешанных файлов `viking://` и действие `Commit Now`.
- **Theme Role (Роль темы)**: Именованное назначение цвета или шрифта (`panelSurface`, `labelTertiary`, `stateError`), за которым закреплено свойство темы DSH. Плагин обращается к теме только через роли: свойство, которого тема не объявляет, падает на fallback молча.
- **Session Read (Чтение сессии)**: Исход запроса состояния сессии. Различает `ok`, `unauthorized`, `missing`, `unreachable` и `error`: демон с `auth_mode: api_key` отвечает на `/health`, но отказывает на сессии, и «нечитаемо» нельзя показывать как «накоплено ноль».
