# Руководство по запуску dsh-review для проекта @dipertq/dsh-openviking-status

Этот документ описывает запуск нативной кампании ревью через установленный плагин `dsh-review` в DSH.

---

## Вариант 1. Запуск через нативный пресет "Review" (DSH Web)

В DSH Web уже установлен хостовый сервис `dsh-review` и политика делегирования `dsh-review-policy` (поддерживающая воркеров Gemini Flash, Claude Opus и Grok).

### Шаги запуска:

1. **Переключение пресета:**
   В окне чата DSH Web (в правом верхнем углу или в свойствах сессии) переключите пресет агента на **`Review`** (либо откройте новый диалог с пресетом `Review`).
2. **Инициализация плана:**
   В чате дайте команду:
   ```text
   Запусти review_plan для проекта /var/lib/dsh/DSH-creator/dsh-openviking-status по файлу scripts/prepare-dsh-review-plan.mjs
   ```
   Агент прочитает файлы, построит запечатанный снимок (snapshot) и выдаст команду согласования вида:
   ```text
   /review approve <runId> <planHash>
   ```
3. **Одобрение человеком:**
   Отправьте команду `/review approve ...` в чат. Это санкционирует запуск изолированных воркеров.
4. **Исполнение и судейство:**
   Агент вызовет `review_start`, опросит прогресс через `review_status`, сведёт кандидаты в `review_reconcile`, вызовет независимого судью (`review_judge`) и экспортирует неизменяемый отчёт через `review_export`.

## Вариант 2. Экспертный аудит прямо в текущем диалоге

Если вы хотите получить заключение прямо здесь без переключения чата, в этом диалоге уже запущены параллельные аудиторские агенты по ключевым линзам:

- **Линза безопасности и сети:** проверка Trust Fence, loopback IP parsing, Origin/Host заголовков, CSRF и маскирования токенов.
- **Линза фронтенда и контрактов:** проверка DSH client bundle contract (`window.__ModuleLoader__.load`), парсера контекста `recallParser`, устойчивости к сбоям сети и доступности поповера.
