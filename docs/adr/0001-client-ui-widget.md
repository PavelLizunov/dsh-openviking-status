# ADR 0001: Автономный Client-to-OpenViking UI виджет

## Статус
Принято (Accepted)

## Контекст
В DeepSeek Harness Desktop отсутствует визуальный интерфейс для отслеживания состояния контекстной памяти OpenViking (экспорт сообщений, накопление токенов до коммита, подмешанные сущности).
Штатный плагин `@openviking/dsh-memory-plugin` работает как фоновый Cordis-сервис ядра без веб-компонентов.

## Решение
1. Разработать клиентский UI-плагин `dsh-openviking-status` с регистрацией в слоте `conversation.input.right` / `conversation.input.left`.
2. Архитектура взаимодействия: Прямой HTTP REST опрос локального демона OpenViking (`http://127.0.0.1:1933/api/v1/sessions/dsh-{sessionId}`) из веб-клиента DSH.
3. Опрос выполняется по событию обновления сессии и с фоновым healthcheck-интервалом (15 сек).
4. Предоставить всплывающее окно (Popover) с метриками и кнопкой принудительного коммита (`POST /api/v1/sessions/{sessionId}/commit`).

## Последствия и компромиссы
- **Плюсы**: Полная независимость от обновлений апстримного плагина `@openviking/dsh-memory-plugin`. Легковесность, отсутствие необходимости в межпроцессном RPC DSH.
- **Минусы**: Клиентский бандл должен иметь сетевой доступ к `127.0.0.1:1933` (что выполняется локально в Desktop/Web).
