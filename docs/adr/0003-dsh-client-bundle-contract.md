# ADR 0003: Формат клиентского бандла и способ занятия слота DSH

## Статус

Принято (Accepted)

## Контекст

Первые версии плагина собирали клиентскую половину обычным CJS/ESM-бандлом и
регистрировали виджет через `ctx.inject(["slots"], scope => ...)`. Плагин
устанавливался, объявлялся бандлом, но при старте DSH падал:

```
client-modules: bundle /plugins/??<...>&rev=<...> loaded without registering
"@openviking-community/dsh-openviking-status" via __ModuleLoader__.load
```

Разбор `@deepseek-ai/dsh-client-modules` и рабочих плагинов
(`@dsh-external/dsh-omniroute-models`, `dsh-better-sidebar`) выявил два
независимых несоответствия контракту.

### 1. Клиентский бандл — не модуль

DSH склеивает клиентские половины всех плагинов в один combo-URL и подаёт его
браузеру как `<script>`. В этой области видимости нет ни `exports`, ни `module`,
ни `import`. Обычный CJS-вывод падает на первом же обращении к `exports` —
до того, как дойдёт до регистрации, поэтому загрузчик и сообщает, что бандл
«загрузился, но себя не зарегистрировал».

Контракт: исполнение файла обязано **синхронно** вызвать
`window.__ModuleLoader__.load({ id, factory })`, где `id` совпадает с именем
пакета, а `factory(require)` возвращает `module.exports`. Зависимости (`react`)
запрашиваются через переданный `require`, а не импортом.

### 2. Регистрация в слоте

`conversation.input.right` — списочный слот со скоупом сессии. Ячейка
адресуется парой `name` (ключ слота) + собственный `id`. Прежний код передавал
в `name` несуществующий ключ `conversation.input.openviking-status` и
самодельную `inject`-фабрику.

Важное следствие скоупа: владелец слота сам отдаёт `sessionId` стандартным
пропом. Чтение `window.__DSH_STORE__` было лишним.

## Решение

1. **Три артефакта сборки** (`tsup.config.ts`):
   - `lib/index.js` — хостовая половина, обычный ESM для Cordis.
   - `lib/client.cjs` — браузерная половина: CJS-тело, завёрнутое баннером и
     футером в вызов `window.__ModuleLoader__.load`. Именно этот файл указан в
     `exports["./client"].default`, который DSH читает буквально.
   - `lib/client.js` — тот же код обычным ESM. Завёрнутый бандл импортировать
     нельзя, а Node не исполняет JSX напрямую, поэтому тесты и потребители
     типов ходят сюда через условие `import`.

2. **Регистрация через `ctx.effect` + `ctx.slots`**:

   ```ts
   ctx.effect(
     () =>
       ctx.slots.inject("conversation.input.right", () =>
         ctx.slots.register(
           {
             name: "conversation.input.right",
             id: "openviking-status",
             order: 50,
           },
           OpenVikingStatusChip
         )
       ),
     "openviking-status: composer chip"
   );
   ```

   `ctx.effect` обязателен: он привязывает disposer к жизненному циклу плагина,
   иначе ячейка переживёт выгрузку.

3. **Контрактный тест** (`tests/clientBundle.test.ts`) исполняет собранный
   `lib/client.cjs` в подставном окружении ровно так, как это делает браузер, и
   проверяет факт регистрации, форму экспортов и занятие ячейки. Юнит-тесты на
   исходники такую регрессию увидеть не могут: ошибка живёт в формате сборки.

## Последствия и компромиссы

- **Плюсы**: сбой формата ловится тестом до релиза, а не Recovery Mode на машине
  пользователя. Костыль чтения глобального стора удалён.
- **Минусы**: клиентский код собирается дважды. Это цена того, что артефакт для
  браузера принципиально неимпортируем.
- **Ограничение**: `exports["./client"]` DSH резолвит только как строку или
  объект со строковым `default` — условия вроде `browser` там не работают.
